работы с основными разделами, принципы хранения данных в базе SQL Server и

================================================================================
1. ОБЩИЕ СВЕДЕНИЯ
================================================================================

Lesson Link — клиентское WPF-приложение для Windows, предназначенное для
автоматизации работы учебного центра или другой образовательной организации.

Ключевые особенности:
  • Одна общая база данных SQL Server обслуживает сразу несколько организаций.
  • Данные каждой организации логически изолированы (мультитенантность).
  • Два основных типа пользователей: Администратор и Преподаватель.
  • Все операции с данными выполняются через защищённые SQL-запросы с
    параметрами и обязательной фильтрацией по организации пользователя.

После запуска открывается окно авторизации. В зависимости от роли пользователя
открывается соответствующая главная панель — администратора или преподавателя.


================================================================================
2. ВХОД В СИСТЕМУ И РЕГИСТРАЦИЯ
================================================================================

2.1. Авторизация
----------------
На главном окне введите:
  • Логин — адрес электронной почты (email), указанный при регистрации.
  • Пароль.

При нажатии кнопки входа приложение:
  1. Проверяет, что поля заполнены.
  2. Вычисляет SHA-256 хеш введённого пароля.
  3. Сравнивает хеш с записью в таблице dbo.[User] по email.
  4. Дополнительно проверяет, что учётная запись активна (IsActive = 1).
  5. Загружает сведения об организации пользователя и её статусе.
  6. Применяет правила допуска (LoginAccessPolicy):
       — заблокированный пользователь не может войти;
       — преподаватель не может войти, если организация неактивна;
       — администратор может войти даже при неактивной организации
         (для восстановления и настройки).
  7. Сохраняет данные пользователя в сессии (AppSession.CurrentUser).
  8. Открывает панель Admin или Teacher в зависимости от роли.

Пароль в базе данных НИКОГДА не хранится в открытом виде — только хеш SHA-256.

2.2. Регистрация новой организации
----------------------------------
Если у вас ещё нет учётной записи:
  1. На окне входа нажмите ссылку регистрации.
  2. Заполните поля:
       — Email (логин) — проверяется по стандарту RFC 5322;
       — Пароль — не менее 6 символов, заглавная и строчная буквы, цифра;
       — Подтверждение пароля — должно совпадать с паролем;
       — Наименование организации — обязательное поле (не короче 2 символов).
  3. Система проверит, что email ещё не занят другим пользователем.
  4. На следующем шаге (OrganizationSetupWindow) укажите реквизиты
     организации: город, адрес, телефон, email организации, ФИО владельца,
     тарифный план.
  5. При сохранении в одной транзакции создаются:
       — запись в dbo.[Organization];
       — учётная запись администратора в dbo.[User];
       — запись учётных данных в dbo.UserCredential.

Каждая новая регистрация создаёт ОТДЕЛЬНУЮ организацию с собственным
идентификатором OrganizationId. Администратор привязывается к этой
организации и видит только её данные.


================================================================================
3. ФУНКЦИИ АДМИНИСТРАТОРА ОРГАНИЗАЦИИ
================================================================================

После входа администратор попадает на главную панель с карточками разделов.
Каждый раздел открывается отдельным окном или экраном.

3.1. Организация
----------------
Раздел «Организация» (OrganizationProfileWindow):
  • Просмотр и редактирование карточки своей организации.
  • Поля: полное и краткое наименование, юридическое лицо, ИНН, адреса,
    контакты, данные владельца, лицензия, лимиты (ученики, преподаватели,
    группы, объём хранилища), статус активности, пробный период, срок
    подписки.
  • Изменения сохраняются только для организации текущего администратора
    (WHERE Id = @OrganizationId пользователя).
  • Флаг IsActive организации влияет на возможность входа преподавателей.

3.2. Направления
----------------
Раздел «Направления» (DirectionManagementWindow):
  • Ведение справочника направлений обучения (DirectionDict).
  • Добавление, изменение и удаление направлений.
  • Направления используются при создании групп и назначении специализации
    преподавателям.
  Примечание: справочник направлений является общим для всей системы
  (не привязан к OrganizationId). Это упрощает единообразие классификации
  курсов.

3.3. Преподаватели в группах
----------------------------
Раздел «Преподаватели в группах» (TeacherGroupAssignmentWindow):
  • Назначение преподавателей на учебные группы.
  • Таблица связей TeacherGroup хранит UserId, GroupId и OrganizationId.
  • Преподаватель получает доступ только к тем группам, на которые он
    назначен в рамках своей организации.

3.4. Зачисление учеников
------------------------
Раздел «Зачисление учеников» (StudentEnrollmentWindow):
  • Зачисление ученика в группу и отчисление из группы.
  • Поиск ученика: введите имя или фамилию в поле «Ученик» — под полем
    появится список совпадений; выберите нужного ученика кликом или Enter.
  • Выбор группы — из выпадающего списка групп своей организации.
  • Таблица внизу показывает все записи StudentGroup (зачисления и
    отчисления) только для текущей организации.

3.5. Сотрудники
---------------
Раздел «Сотрудники» (TeacherManagementView):
  • Управление учётными записями сотрудников (преподавателей и администраторов).
  • Добавление, редактирование, блокировка (IsActive).
  • Поля: ФИО, email, телефон, адрес, роль, специализация, дата найма, пароль.
  • Все сотрудники создаются с OrganizationId текущей организации.
  • Пароль нового сотрудника сохраняется в виде SHA-256 хеша.

3.6. Группы
-----------
Раздел «Группы» (GroupManagementView):
  • Создание и редактирование учебных групп.
  • Параметры: название, направление, уровень, возрастная категория,
    формат занятий, статус набора, максимальное число учеников, стоимость
    в месяц, аудитория, описание, активность.
  • При создании группе автоматически присваивается OrganizationId
    администратора.
  • Удаление выполняется через деактивацию (IsActive = 0), а не физическое
    удаление записи.

3.7. Расписание
---------------
Раздел «Расписание» (ScheduleView):
  • Планирование занятий по группам организации.
  • Поля занятия: дата и время, тема, длительность, аудитория, ссылка
    на онлайн-занятие, отмена с указанием причины.
  • Фильтрация по дате или просмотр всего расписания организации.
  • Все операции (SELECT, INSERT, UPDATE, DELETE) содержат условие
    OrganizationId = @OrganizationId.

3.8. Дети (ученики)
-------------------
Раздел «Дети» (StudentManagementView):
  • Полный реестр учеников организации.
  • Карточка ученика: имя, фамилия, отчество, пол, дата рождения,
    возрастная группа, статус активности, данные родителя, адрес,
    медицинские показания, дата зачисления.
  • Поиск по ФИО и другим полям.
  • Фильтр «Только активные ученики».
  • Добавление, редактирование, деактивация учеников.

3.9. Методика
-------------
Раздел «Методика» (MaterialsView):
  • Загрузка и управление методическими материалами по группам.
  • Файлы сохраняются на диск в папку вида:
      Materials\Org_{OrganizationId}\Group_{GroupId}\
    что обеспечивает физическое разделение файлов разных организаций.
  • Метаданные (название, описание, путь к файлу) хранятся в таблице
    dbo.[Material] с полем OrganizationId.
  • Удаление и изменение возможны только для записей своей организации.

3.10. Успеваемость и посещаемость
---------------------------------
Раздел «Успеваемость и посещаемость» (StudentHistoryWindow):
  • Просмотр истории посещаемости и оценок любого ученика организации.
  • Поиск ученика по имени или фамилии (ручной ввод с подсказками).
  • Таблица посещаемости: дата занятия, группа, статус, время отметки.
  • Таблица оценок: дата, группа, тип оценки, значение.
  • Данные загружаются с фильтром OrganizationId и StudentId.


================================================================================
4. ФУНКЦИИ ПРЕПОДАВАТЕЛЯ
================================================================================

Преподаватель после входа видит собственную главную панель с ограниченным
набором разделов. Доступ определяется двумя факторами:
  1) OrganizationId — принадлежность к организации;
  2) TeacherGroup — назначение на конкретные группы.

4.1. Личные данные
------------------
Раздел «Личные данные» (TeacherProfileView):
  • Просмотр и редактирование своего профиля.
  • Смена пароля: требуется ввод текущего пароля, новый пароль проверяется
    по тем же правилам сложности, что при регистрации.
  • Обновление выполняется с условием Id = @UserId AND OrganizationId =
    @OrganizationId — преподаватель не может изменить чужую запись.

4.2. Мои группы
---------------
Раздел «Мои группы» (TeacherGroupsView):
  • Список групп, на которые преподаватель назначен через TeacherGroup.
  • Отображаются только группы своей организации (g.OrganizationId = @OrgId
    AND tg.UserId = @UserId).

4.3. Моё расписание
-------------------
Раздел «Моё расписание» (TeacherScheduleView):
  • Расписание занятий только по группам преподавателя.
  • Фильтрация по выбранной дате.
  • SQL-запрос связывает Schedule, Group и TeacherGroup с проверкой
    OrganizationId на каждом уровне.

4.4. Мои ученики
----------------
Раздел «Мои ученики» (TeacherStudentsView):
  • Список учеников, зачисленных в группы преподавателя.
  • Ученик отображается только если:
       — он принадлежит той же организации (s.OrganizationId = @OrgId);
       — он зачислен в группу (StudentGroup, LeaveDate IS NULL);
       — преподаватель назначен на эту группу (TeacherGroup).
  • Поиск, фильтр активных, просмотр карточки ученика.
  • Преподаватель НЕ видит учеников других групп и других организаций.

4.5. Посещаемость
-----------------
Раздел «Посещаемость» (TeacherAttendanceWindow):
  • Два режима: отметка по занятию и просмотр истории по ученику.
  • По занятию: выберите дату → занятие из своего расписания → отметьте
    присутствие учеников → «Сохранить».
  • Перед сохранением выполняются дополнительные проверки безопасности:
       — TeacherOwnsSchedule: занятие принадлежит группе преподавателя;
       — IsStudentInTeacherGroup: ученик зачислен в группу этого занятия.
  • Запись сохраняется в dbo.LessonAttendance с OrganizationId, ScheduleId,
    StudentId, IsPresent, MarkedByUserId, MarkedAt.
  • Нельзя сохранить посещаемость для отменённого занятия.

4.6. Оценки
-----------
Раздел «Оценки» (TeacherGradesWindow):
  • Выставление оценок ученикам своих групп.
  • Запись в dbo.StudentGrade с OrganizationId, StudentId, GroupId,
    TeacherUserId, типом и значением оценки.
  • Доступны только ученики и группы в рамках назначения преподавателя.

4.7. Методика (преподаватель)
-----------------------------
Раздел «Методика» (TeacherMaterialsView):
  • Просмотр методических материалов по своим группам.
  • Фильтрация: Material.OrganizationId = @OrgId и группа входит в
    TeacherGroup текущего преподавателя.


================================================================================
5. ПОИСК УЧЕНИКОВ
================================================================================

В нескольких разделах реализован единый принцип ручного поиска:
  • Зачисление учеников (StudentEnrollmentWindow);
  • Успеваемость и посещаемость (StudentHistoryWindow);
  • Дети — расширенный поиск по многим полям (StudentManagementView).

Как пользоваться:
  1. Начните вводить имя или фамилию в текстовое поле.
  2. Под полем появится список совпадений (без учёта регистра).
  3. Выберите ученика из списка или нажмите Enter (если найден один).
  4. При нескольких совпадениях система попросит уточнить выбор.

Логика поиска вынесена в класс StudentSearchHelper и проверяется
юнит-тестами.


================================================================================
6. РАБОТА С БАЗОЙ ДАННЫХ
================================================================================

6.1. Общая архитектура
----------------------
Приложение использует реляционную СУБД Microsoft SQL Server.
База данных: Lesson.
Экземпляр сервера (по умолчанию): localhost\SQLEXPRESS01.
Подключение: Integrated Security (Windows-аутентификация).

Строка подключения задаётся в файле Helpers\DatabaseHelper.cs:
  Server=localhost\SQLEXPRESS01;Database=Lesson;Integrated Security=True;Encrypt=False;

Все экраны приложения обращаются к базе через класс DatabaseHelper и
прямые SQL-запросы (Microsoft.Data.SqlClient). Отдельного сервера
приложений или веб-API нет — безопасность реализуется на уровне
клиентского приложения и SQL-фильтров.

6.2. Основные таблицы и их назначение
--------------------------------------
  dbo.[Organization]     — организации (учебные центры); корневая сущность
                           мультитенантности.
  dbo.[User]             — пользователи системы; каждый привязан к OrganizationId.
  dbo.UserCredential     — дополнительные учётные данные (хеш пароля, блокировки).
  dbo.RoleDict           — справочник ролей (Admin, Teacher).
  dbo.[Student]          — ученики; OrganizationId обязателен.
  dbo.[Group]            — учебные группы; OrganizationId обязателен.
  dbo.[StudentGroup]     — зачисление ученика в группу (JoinDate, LeaveDate).
  dbo.[TeacherGroup]     — назначение преподавателя на группу.
  dbo.[Schedule]         — расписание занятий; OrganizationId обязателен.
  dbo.LessonAttendance   — посещаемость на занятии.
  dbo.StudentGrade       — оценки учеников.
  dbo.[Material]         — методические материалы (метаданные файлов).
  dbo.DirectionDict      — справочник направлений (общий).
  dbo.AgeGroupDict       — справочник возрастных групп (общий).
  dbo.SubscriptionPlanDict — тарифные планы.

6.3. Скрипт расширения схемы
----------------------------
Файл SchemaExtensions.sql добавляет:
  • поля карточки ученика (MiddleName, Gender, MedicalNotes);
  • таблицы LessonAttendance и StudentGrade;
  • дополнительные поля Organization, User, Group, Schedule.

Скрипт выполняется один раз администратором базы данных. Без него часть
функций (посещаемость, оценки, расширенная карточка) работать не будет.

6.4. Транзакции
---------------
Критически важные операции выполняются в транзакциях:
  • Регистрация организации и администратора (RegisterOrganizationWithAdmin).
  • При ошибке на любом шаге транзакция откатывается (Rollback), данные
    не остаются в «полусозданном» состоянии.

6.5. Параметризованные запросы
-------------------------------
Все пользовательские значения передаются через SqlParameter (@Email,
@OrganizationId, @UserId и т.д.), а не подставляются в строку запроса.
Это защищает от SQL-инъекций: даже если злоумышленник введёт в поле
ввода фрагмент SQL-кода, он будет обработан как обычный текст.


================================================================================
7. БЕЗОПАСНОСТЬ ДАННЫХ
================================================================================

7.1. Аутентификация (кто вы)
-----------------------------
  • Вход только по паре email + пароль.
  • Пароль хешируется алгоритмом SHA-256 перед сравнением с базой.
  • В интерфейсе и в базе не хранится исходный пароль.
  • Неверный логин или пароль — единое сообщение «Неверный логин или пароль»
    (не раскрывается, существует ли email).
  • Учётная запись с IsActive = 0 не проходит аутентификацию.
  • При успешном входе обновляется LastLoginDate (если столбец существует).

7.2. Авторизация (что вам разрешено)
------------------------------------
После входа роль пользователя определяет доступный интерфейс:
  • Admin  → AdminDashboardView (полное управление организацией).
  • Teacher → TeacherDashboardView (ограниченный набор разделов).

Дополнительные ограничения для преподавателя:
  • Только группы из TeacherGroup.
  • Только ученики, зачисленные в эти группы.
  • Только занятия своих групп при отметке посещаемости.
  • Блокировка входа при неактивной организации.

7.3. Сессия пользователя
------------------------
После успешного входа объект User сохраняется в AppSession.CurrentUser.
Все экраны получают User через конструктор (_admin, currentUser, _teacher)
и используют его OrganizationId и Id при каждом запросе к базе.

Метод AppSession.RequireOrganizationId() выбрасывает исключение, если
сессия не установлена — это защита от обращений к данным без авторизации.

7.4. Защита паролей при регистрации и смене
-------------------------------------------
При регистрации (RegistrationValidation):
  • Email проверяется по RFC 5322.
  • Пароль: минимум 6 символов, заглавная, строчная буква, цифра.
  • Подтверждение пароля должно совпадать.

При смене пароля преподавателем:
  • Проверяется текущий пароль (сравнение хешей).
  • Новый пароль проходит те же правила сложности.

7.5. Защита от несанкционированного изменения данных
----------------------------------------------------
При UPDATE и DELETE практически везде используется двойное условие:
  WHERE Id = @Id AND OrganizationId = @OrganizationId

Это означает: даже если пользователь каким-то образом узнает числовой Id
записи другой организации, приложение не сможет её изменить или удалить,
потому что OrganizationId в запросе берётся из сессии текущего пользователя,
а не из ввода пользователя.

Для преподавателя добавляется третий уровень — проверка TeacherGroup
и StudentGroup перед сохранением посещаемости и оценок.

7.6. Файловое хранилище
-----------------------
Методические материалы на диске размещаются в каталогах с префиксом
Org_{OrganizationId}, что предотвращает случайное смешивание файлов
разных организаций на уровне файловой системы.

7.7. Подключение к SQL Server
-----------------------------
Используется Integrated Security — доступ к базе определяется учётной
записью Windows, под которой запущено приложение. Для промышленной
эксплуатации рекомендуется:
  • ограничить права SQL-логина или Windows-группы только базой Lesson;
  • не запускать приложение под учётной записью администратора Windows;
  • включить резервное копирование базы данных.

8. ИЗОЛЯЦИЯ ДАННЫХ МЕЖДУ ОРГАНИЗАЦИЯМИ
================================================================================

Это ключевой принцип архитектуры Lesson Link. Несколько учебных центров
работают в одной базе данных, но не видят данные друг друга.

8.1. Модель мультитенантности
-----------------------------
Тип изоляции: «общая база, общие таблицы, разделение по столбцу OrganizationId».

Каждая бизнес-запись (ученик, группа, расписание, материал, посещаемость,
оценка, назначение преподавателя) содержит поле OrganizationId — числовой
идентификатор организации-владельца.

При регистрации создаётся новая организация с уникальным Id. Все последующие
данные, создаваемые администратором этой организации, получают тот же
OrganizationId.

8.2. Как это работает на практике
---------------------------------
Пример 1 — администратор просматривает учеников:
  SELECT ... FROM dbo.[Student] s
  WHERE s.OrganizationId = @OrganizationId
  -- @OrganizationId = 5 (ID организации администратора)
  -- Ученики организации 7 в результат не попадут.

Пример 2 — преподаватель видит расписание:
  SELECT ... FROM dbo.[Schedule] s
  INNER JOIN dbo.[TeacherGroup] tg ON s.GroupId = tg.GroupId
  WHERE tg.UserId = @UserId
    AND s.OrganizationId = @OrgId
  -- Преподаватель видит только занятия своих групп своей организации.

Пример 3 — сохранение посещаемости:
  INSERT INTO dbo.LessonAttendance (OrganizationId, ScheduleId, ...)
  VALUES (@OrgId, @SchedId, ...)
  -- OrganizationId берётся из сессии преподавателя, а не из формы.

8.3. Цепочка доверия при входе
------------------------------
  1. Пользователь вводит email и пароль.
  2. Authenticate находит запись в dbo.[User] и читает OrganizationId.
  3. JOIN с dbo.[Organization] загружает статус организации.
  4. User сохраняется в AppSession.
  5. Каждый экран использует user.OrganizationId во всех SQL-запросах.

Таким образом, OrganizationId никогда не выбирается пользователем
вручную в интерфейсе — он определяется только при аутентификации.

8.4. Разграничение Admin vs Teacher внутри одной организации
------------------------------------------------------------
Внутри одной организации администратор и преподаватель имеют разный объём
доступа:

  Администратор:
    • все ученики организации;
    • все группы, расписание, сотрудники;
    • зачисление, настройка организации, материалы всех групп.

  Преподаватель:
    • только свои группы (TeacherGroup);
    • только ученики этих групп;
    • посещаемость и оценки только по своим занятиям;
    • редактирование только своего профиля.

8.5. Что является общим для всех организаций
--------------------------------------------
Некоторые справочники не привязаны к OrganizationId и доступны всем:
  • DirectionDict (направления обучения);
  • AgeGroupDict (возрастные группы);
  • RoleDict (роли);
  • SubscriptionPlanDict (тарифы).

Это нормально для справочных данных. Конфиденциальные данные (ученики,
родители, оценки, посещаемость, сотрудники) всегда привязаны к организации.

8.6. Email как глобально уникальный логин
-----------------------------------------
Email пользователя уникален во всей системе (не только внутри организации).
При регистрации проверяется IsEmailRegistered — один email не может
принадлежать двум организациям. Это упрощает вход: система однозначно
определяет пользователя и его OrganizationId.

9. СХЕМА ПОТОКА ДАННЫХ (КРАТКО)
================================================================================

  [Пользователь]
       |
       v
  [Окно входа] --SHA-256--> [dbo.[User] + dbo.[Organization]]
       |
       v
  [AppSession.CurrentUser]  (Id, Role, OrganizationId, ...)
       |
       +-- Admin --> экраны с фильтром OrganizationId = user.OrganizationId
       |
       +-- Teacher --> экраны с OrganizationId + TeacherGroup.UserId

  Любой INSERT: OrganizationId = user.OrganizationId (из сессии)
  Любой SELECT: WHERE OrganizationId = user.OrganizationId (+ роль)
  Любой UPDATE/DELETE: WHERE Id = @Id AND OrganizationId = user.OrganizationId

10. РЕКОМЕНДАЦИИ ПО ЭКСПЛУАТАЦИИ
================================================================================

  • Регулярно выполняйте резервное копирование базы Lesson.
  • Храните файл SchemaExtensions.sql и применяйте его при развёртывании.
  • Не передавайте пароли сотрудникам по незащищённым каналам.
  • Блокируйте (IsActive = 0) уволенных сотрудников, а не удаляйте записи.
  • Для деактивации всей организации снимите флаг IsActive в карточке
    организации — преподаватели не смогут войти, администратор сможет
    восстановить настройки.
  • Перед обновлением приложения убедитесь, что база данных доступна
    и строка подключения в DatabaseHelper.cs соответствует вашему серверу.
